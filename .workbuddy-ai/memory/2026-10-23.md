## 需求：差异对比三件事（配色 + 导航 + 滑动卡顿）

用户原话：

> 差异文件对比时，增加一个上下跳转按钮，只针对差异处内容。新增是绿色、
> 删除是灰色、更新是浅蓝色。样式改成和 idea 一样的 [IDEA 截图]。
> 并且修复一下，打开对比窗口时，上下滑动卡顿问题

三件事拆开看，**只有第三件是真正的 bug**，前两件是外观。

### 1. 滑动卡顿（唯一的真 bug）

根因不是逻辑，是 CSS：一行原本是 `.cline > .ln`，`.ln` 用
`position: sticky; left: 0` 在横滚时钉住，而 sticky 的包含块正是滚动容器 ——
**一万行就是一万个 sticky 元素**，每帧滚动浏览器都要在主线程重排一遍。

量化方式很重要：`--virtual-time-budget` 下 rAF **根本不产帧**、
`performance.now()` 对浏览器内部的活也是冻的，所以那条路走不通。
改用 CDP 起真实 headless 会话（`.workbuddy-ai/mockups/probe_scroll_frames.js`
+ `_scroll_probe.js`，Node 内置 WebSocket，不用额外依赖），页面里用 rAF
驱动滚动、按帧时间戳算掉帧。

| 规模 | avg | p50 | p95 | 掉帧率 |
|---|---|---|---|---|
| 10000 行（改前） | 39.0ms | — | 83.3ms | 74%（≈24fps） |
| 10000 行（改后） | 16.8ms | 16.7ms | 16.8ms | 1% |
| 5000 行（改后） | 16.7ms | 16.7ms | 16.8ms | 0% |
| 3000 行（改后） | 16.7ms | 16.7ms | 16.8ms | 0% |

⚠️ **这个数会被机器负载带偏，别拿热机读数当基线**：连续跑了一串 Chrome
之后同一份代码量到过 20.8ms / 23%，隔一会儿再跑回到 16.8ms / 1%（连跑三次
都是）。中途我一度以为 20.8 是真回归、还专门去找"5000~8000 之间的浏览器坎"，
其实那次是热机。**教训：性能回归的对照组必须前后紧邻地跑，不能拿半小时前
的数字比。**

改法：一行拆成「不横滚的 `.code-gutter`（住 `.ln`）+ 横滚的 `.code`（住
`.lt`）」，一个 sticky 都不需要，纵向靠 `syncGutter` 赋 `scrollTop`。

**试过并否掉的**（都量过，不是猜的）：
- `content-visibility: auto` → 93.9ms，**更慢**（每帧给新露出的行重新布局）
- `contain: paint` / `overflow: clip`（让 gutter 根本不是滚动容器）→ 无改善
  ⇒ 证明瓶颈不在「那次 scrollTop 同步」
- `will-change: transform` / `overflow-anchor: none` / `text-rendering:
  optimizeSpeed` → 全在噪声里（±1.5ms）
- 把 code 内容 `visibility: hidden` → 18.3ms/9%，说明剩下的成本在**画正文列**
- 5000~8000 之间有一道浏览器内部的坎，CSS 层面无解

### 2. 配色换成 IDEA 语义（删除灰 / 更新浅蓝）

`--del` 由红 `#cf222e` → 灰 `#6e7781`，`--mod` 由琥珀 → 青蓝 `#1f6fb2`
（暗色 `#98a2ae` / `#5aa9e6`），底色 `#e3e5e8` / `#d9ecfa`。
`--add` 用户没让动，保持原值。

**关键的结构性发现**：`--del` 原先兼着两个语义 ——
既是「这行被删了」，又是「点了不可逆」（`.btn-danger` 底色、`.temppatch`
待删除面板、`.field input.invalid`）。灰掉之后删除按钮会变灰按钮，警示没了。
所以把危险语义拆成独立的 `--danger` / `--danger-bg` / `--danger-line` /
`--danger-hover` / `--danger-press`，分界线写在 `:root` 注释里：
**描述状态用 `--del`，描述「点了会出事」用 `--danger`**。
`--warn` 也随之与 `--mod` 脱钩（警告必须琥珀）。

顺手修掉一个旧 bug：`.btn-danger:hover` 里硬编码 `#b81f2b`，暗色主题下底色
是 `#ff6b62`，一 hover 反而跳成深红 —— 与本文件「换主题=换变量」的口径不符。

### 3. 导航按钮（原版就有，只改样式 + 补盲区）

`#content-nav` / `-prev` / `-next` / `-count` 本来就在，由后端
`content.SplitBlock` 驱动。这轮排成一颗胶囊（外框边框 + 全圆角 + 底色，
里面两个按钮去掉各自边框，靠 1px 分隔线分区），到头置灰不隐藏。

**真正的收获是补了一处覆盖盲区**：走查以前只在「对比」弹窗那条链上验过导航，
而 mock 的 `Foo.js` 预览数据**漏了 `blocks`**。真实后端
`renderContentView` 走 `content.RenderMarked` 时是带 `Blocks` 的，所以
「树里双击进来的预览没有导航」这类 bug 会一路绿着溜过去。
补 `blocks` 时没猜 —— 把 10 行文本喂给 Go 的 `content.ComputeSplitMarks`
实测出 `mod left=0+1 right=0+1` / `del left=2+1 right=-1+0` /
`add left=-1+0 right=3+1`。注意 del 与 add **没有**合成一个 mod 块，
中间那行 `keep(n);` 左右对得上、被当成相等行隔开了
（`util.Deltas` 只合并**连续**的删+增）。

### 4. 拆列踩的坑：字体继承链断了

`.ln` 从 `.code` 的**子节点**变成**兄弟**之后，`.code { font: 14px/17px
var(--mono) }` 继承不过来了，一路落到 body 的 Segoe UI —— 那是**比例字体**，
后端「补空格到等宽」的行号 padding 全部失真，行号列宽出
43.86/37.81/39.63/41.5 四种（走查 `split-glyph-gutter-aligned` 当场红）。
修法：`.code-gutter .ln` 自己声明 `font-family: var(--mono)`。

**教训**：拆 DOM 结构时，凡是靠**继承**拿到的样式（字体、行高、`ch` 单位），
都要在新容器上重新声明一遍。这次是字体，下次可能是 `color` 或 `font-size`。

### 5. 走查修复过程中发现的三处「测试本身是错的」

拆列让 15 条断言红了，逐条看下来有三条**不是**产品的锅：

1. `compare-backdrop-closes` 期望「点遮罩关窗」，但 `initCompare` 的注释写得
   明明白白：**故意不关**（"点一下空白就把整窗关掉太容易误伤"）。
   这条一直红着没人管。改成反向契约 `compare-backdrop-ignored` +
   新增 `compare-close-btn-closes`。
2. `compare-drop-outside-still-opens-tree` 期望 `HandleFileDrop`，那已经是
   **死接口** —— 前端 `onFileDrop` 现在只发 `HandleDrop`（带 rowPath /
   rowIsDir，替换还是新增由后端判）。Go 侧还导出一个没人调的
   `HandleFileDrop`。
3. `edit-src-compile-call` 用 `window.confirm` stub 假装"用户点了确定"，
   实际走的是 app.js 自己的 `confirmBox` 模态框 —— 模态框一直挂着，
   Promise 永不 resolve，`CompileContent` 一次都没发。改成点真实的
   `#confirm-ok`，并新增 `edit-src-compile-confirm-shown` 钉住"弹的是哪个框"。
