### 语义（对照 Java 原版 HomeLeftTreeView）

- **删除（delete）**：物理摘节点（`RemoveNodeChild`），统计记 `MANUAL_DEL`（manualDelTotal）。节点从树上消失，写包时遍历不到。弹确认框。
- **标记删除（markDelete）**：节点留在树上，状态设为 `DEL`（delTotal）。写包时 `writeTreeNode2Pack` 判断 DEL 跳过不写，并记 delInfo。是 RadioMenuItem 切换项，再点一次取消标记。

两者是独立计数，分别写进 patch-up.sign 的 `manualDelTotal` / `delTotal` 字段。

### 踩过的坑（重要）

1. **`appendManualDel` 参数名不副实踩出真 bug**：函数签名 `(jarPath, action)` 但 `jarPath` 传的是**节点路径**，导致存进去的是 jar 文件路径而不是节点路径。改成 `(jarPath, nodePath, action)` 三参数。症状是"落盘了但重应用找不到节点"，很难查。
2. **测试污染真实配置目录**：`NewApp()` 会初始化真实 `%APPDATA%` 的 store，任何跑 `OpenAppPack` 的测试都会读它。调试时写进去一条 `app.jar` 的删除记录，直接让 `TestSaveContentFlowsIntoPatchOutput` 变红。修法：`newAppZh()` 里把 `manualDelStore` 置 nil，只有测持久化的用例用 `newTestApp(t)`。**以后新增任何持久化能力都要照这个套路**。

## 拖进去变"下载" —— app.js 整份语法错误（已修）

用户报障（截图）：把 jar 拖进窗口，右上角弹出 WebView2 的「下载」面板（同一个 jar 连着下载了 3 份，`(1)` `(2)` 是浏览器去重命名）。

### 根因

`app.js` 有**语法错误**，整份文件解析失败 → 一行都没执行：

```
app.js:487  SyntaxError: Unexpected identifier 'li'
```

`renderTempPatch()` 在 484 行已经完整收尾，但下面还留着一段**重复的尾巴**
（`li.appendChild(sz);` / `}` / `li.addEventListener(...)` / `ul.appendChild(li);` / `});` / `}`）——
上一轮改"清单显示完整路径"时用 Edit 替换，只替换了前半段、没删掉旧的后半段。

后果链条（这是这次最值得记的）：

1. 整份 app.js 不执行 → `init()` 一次都没跑；
2. HTML/CSS 照常渲染，所以界面**看起来完全正常**（工具栏、双面板、`未打开` 都在）；
3. 所有 `addEventListener` 绑定全丢：按钮没反应、右键菜单不出来；
4. `initDrop()` 没跑 → `window.runtime.OnFileDrop(cb, true)` 没注册 →
   Wails 运行时的 `dragover`/`drop` 监听器压根没挂上（它们是在 `OnFileDrop` 里挂的，
   见 wails v2 `internal/frontend/runtime/desktop/draganddrop.js` 的 `OnFileDrop`）；
5. 于是拖入文件落回 WebView2 的浏览器默认行为 → **把文件当下载**。

### 为什么之前怀疑错方向

先把 Wails 侧翻了个底朝天（`draganddrop.js` 的 `onDragOver`/`onDrop` 无条件
`preventDefault`、`EnableFileDrop` 在 `main.go` 里没动、`--wails-drop-target: drop`
还在 `.pane` 上、v2.14/2.15/2.16 三个版本的 draganddrop.js 完全一致）。
**推理上有个漏洞**：当时默认"app.js 在跑"，因为截图里界面是好的 ——
但界面好看只证明 HTML/CSS 好，不证明 JS 在跑。这类"渲染正常、逻辑全哑"的故障
必须先验语法，再往下查。

### 修法

## 需求：匹配的文件左右用线连起来（先出示例，未动源码）

用户想法：应用树和补丁树里匹配上的文件，用连线把左右两侧连起来，方便看清"这个补丁改的是哪几个位置"。

按要求**先不动源码**，只做了可交互示例稿：

- `.workbuddy-ai/mockups/match-links.html`（自包含，不引 app.js/app.css，配色行高抄的 app.css 真值）
- 同目录 `shot-A.png` / `shot-B.png` / `shot-C.png`：三种画法的静态截图
- 支持 `?v=A|B|C&pin=0&color=1` 直接切到某个方案

三种画法：
- **A 聚焦连线（推荐）**：只画当前选中/悬停那一对，其余不画。补丁包文件顺序和应用树顺序天然不同，全画必交叉。
- **B 全量连线**：全画，选中加粗、其余 34% 透明。6 对以上开始叠。
- **C 正交折线**：横→竖→横。单条好看，多条在窄缝里挤成 Z 字。

示例里定下的几个实现要点（真做的时候照这个来）：
1. 线的端点接在**面板内边缘、行中心高度**，不是行内容右端 —— 左树行是 `width:max-content`，MD5 列常被裁掉，行内容右端不可见。
2. 分隔条从 5px 加宽到 **12px** 当"连线走廊"；B/C 全量模式要 **28px** 才能给每条线分道。
3. 曲线用**两个控制点落在同一条道**的贝塞尔（`C laneX y1, laneX y2`）：离开端点水平、中段竖走、进入对端水平，就是桑基图那种。多条时 laneX 按序号错开。
4. 对端滚出视口时端点**夹到可视边缘** + 画上下小三角，不然线会突然断掉像 bug。
5. 未匹配的行不画线（右侧 common.js / xlsx / README.txt 就是这种情况）。
6. 端点圆点画在 SVG 层（和线端点同位置），**不要**放进 `.row` 里 —— 行宽 max-content，放行尾会被裁掉。

待用户拍板：默认 A 还是 B；是否只在"开启补丁文件比对"时显示；端点圆点留不留。

## 定案 + 实现：匹配连线（方案 B + 端点圆点 + 设置开关）

用户拍板：**按 shot-B 做（全量连线）**，端点圆点保留，显示条件放进设置面板。

### Go 侧（gui/app.go）

- `App.showMappedLinks`：默认 `true`（"这个补丁改了哪儿"最直接的表达）
- `Settings.ShowMappedLinks` / `settingsView()` / `ApplySettings` 三处接线
- `State.MappedLinks []MappedLink{AppDom, PatchDom}`，`state()` 末尾按
  `linksEnabled()`（= `showMappedLinks || settings.PatchFileDiff`）决定是否下发
- `collectDomPaths` + `collectMappedLinks`：走补丁树，取 `!Dir()` 且 MappedNode 落在应用树的成对节点
- **dom 路径**（`r`、`r/0/3`，从根往下的子序号链）是关键设计：不能用 `Node.Path`
  —— 嵌套 jar 里条目的 Path 不带 jar 前缀，两个 jar 都有 `META-INF/MANIFEST.MF` 会撞车。
  规则必须与前端 `makeRow` 的 `dom + '/' + i` 完全一致。

### 前端（app.js / index.html / app.css）

- `#links` SVG 绝对定位盖在 `.panes` 上（`pointer-events:none`，z-index 6）
- `.splitter-v` 5px → **22px** 当连线走廊；`.pane` flex `1 1 50%` → `1 1 0`（50%+50%+走廊会溢出）
- 端点 x = 两侧面板内边缘各往里 2px；`step = clamp((x2-x1-6)/(n-1), 0.9, 5)` 分道
- 设置里新增「总是显示匹配连线」（`#set-show-links`），关掉后跟随「开启补丁文件比对」

### 这次真机上发现并修掉的两个问题

1. **rAF 锁会被永久卡死**（真实缺陷）。`linksSchedule` 原来用 `links.raf` 当锁，
   回调没执行（窗口最小化 / 页面隐藏 / 无头渲染）锁就回不到 0，之后所有重画请求
   全变空操作，连线层从此冻结。改成带时间戳的自愈：超过 200ms 没等到帧就重新排一次。
   排查时正是这个 bug 让无头渲染出的连线数量在 1~9 之间乱跳。
2. **视野外的端点全叠在一个点上**。原来 `linkEnd` 直接把 y 夹到视口边缘，9 条线里
   7 条对端在视野外 → 7 个圆点 + 7 个三角叠成同一个点，看着像只有一个文件。
   新增 `spreadEdges`：按真实 y 的远近沿边排开成一列（间距 8px，最多 12 个），
   最贴边那个画箭头，其余画圆点。

顺带修掉一个自己刚引入的副作用：`applySettings` 里为了刷新连线去调 `apply()` 会重建
两棵树、滚动位置跳回顶部。改成只在开关真的变了时 `GetState` + **只喂 `linksSet`**。
